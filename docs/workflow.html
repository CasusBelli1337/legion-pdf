Legion Armory — Librarius — Workflow Pipelines

How a document moves through the app, and how the two heavy pipelines (OCR, redaction) work.

Document lifecycle

flowchart TD
  A[Open PDF
dialog / drag-drop / recent] --> B[doc-store main process
bytes = source of truth]
  B --> C[Renderer tab
pdfjs renders pages virtualized]
  C --> D{User action}
  D -->|organize / stamp / bates
watermark / signature / text| E[IPC ops:* stamp:*
core/ pure function on bytes]
  E --> F[OpResult: new bytes +
pagesIn/pagesOut verified]
  F --> C
  D -->|Save| G[Write bytes to path]
  D -->|Redact / OCR| H[Heavy pipelines below
always Save-As]

OCR pipeline (local Tesseract, all cores)

flowchart TD
  A[Detect pages without text layer] --> B[Renderer rasterizes pages
300 DPI PNG via pdfjs]
  B --> C[Main: Tesseract worker pool
N = CPU cores, streams Page 37/214]
  C --> D[hOCR word boxes per page]
  D --> E[core/ocr: invisible text layer
written under page image]
  E --> F[Count check: every requested page
produced a result — else LOUD error]
  F --> G[Searchable PDF, Save-As]

True redaction (destruction, then proof)

flowchart TD
  A[Mark boxes: drawn by hand
or search-all-instances] --> B[Apply: affected pages
rasterized at 300 DPI]
  B --> C[Boxes burned black into raster]
  C --> D[Page content REPLACED by raster
original text/images destroyed]
  D --> E[Optional re-OCR of
non-redacted regions]
  E --> F[VERIFY: re-extract text,
assert every target string absent]
  F -->|pass| G[Receipt: N instances destroyed
Save-As only]
  F -->|fail| H[LOUD error — file not written]
