# E-signature live E2E — 2026-08-22

Full round trip of the new F-13 e-signature feature against the REAL deployed
Legion Sign service (sign.legionarmory.net, Cloudflare Worker + D1 + R2),
driven through the built app (driver REPL) and real mailboxes. Test document:
a fictional two-page Delaware board consent ("Meridian Verdict Analytics,
Inc.", directors Eleanor Vance and Marcus Webb — two real mailboxes owned by
the requester stood in for the signers). Evidence pack (screenshots + PDFs):
OneDrive `#Legion/Product/Armory - Librarius/E-Sign-E2E-2026-08-22/`.

## What was proven, in order

1. **Service deploy + security posture (live)** — `/api/health` 200; envelope
   API 401 without/with wrong bearer; invalid signer token → uniform 404
   ("This signing link is not valid or has expired"); SPA serves. D1
   migrations applied; secrets set via wrangler only.
2. **Manual placement** — signer added in panel, Signature armed,
   click-placed on page 2; overlay box + list stay in sync.
3. **Centurion end-to-end (live Opus call)** — asked in plain English to set
   the document up for e-signature. Centurion read the document, asked one
   sensible scoping question (skip name fields — names are pre-printed),
   refused to guess signer emails not present in the document, then proposed
   ONE `addSignatureFields` call: confirm card "Add 4 e-sign fields for 2
   signers to the E-Sign panel (Eleanor Vance: 2, Marcus Webb: 2)". On
   Approve, all four fields landed anchored correctly: signatures ON the two
   "By:" underscore runs (occurrence 1 vs 2 disambiguation), dates right of
   each "Date:" label. Honest receipt; nothing sent.
4. **Send (service delivery)** — request created against the live API;
   "Request sent — Legion Sign emailed each signer their link."
5. **Email delivery** — both request emails arrived in the INBOX (Gmail and
   Workspace), from `Legion Sign <sign@legion.law>`, maroon Review & sign
   button, private-link notice.
6. **Signer 1 (draw path)** — opened her link, guided flow, drew a signature,
   date auto-filled, ESIGN consent checkbox, Finish & sign → "You're all set…
   Awaiting Marcus Webb."
7. **Signer 2 (upload path)** — uploaded a fabricated "photo of a wet
   signature" (dark ink on noisy gray paper); the ported demand-letter
   cleanup ran client-side (before/after preview: paper removed, ink kept);
   applied, consented, finished → "Everyone has signed — the final copy is in
   your email." Scoping held: signer 2's view carried only signer 2's fields.
8. **Finalize + distribution** — envelope completed; final PDF = 3 pages
   (2 original + Signing Certificate: envelope id, UTC timestamps, SHA-256 of
   original, per-signer consent/signed times, IP, UA). "Fully signed:" email
   with the attached `<title> (signed).pdf` arrived in BOTH mailboxes'
   inboxes.
9. **Round-trip status** — panel Refresh showed both signers ✓ Signed
   8/22/2026 and "Everyone signed — final copies emailed."
10. **Final artifact verified** — downloaded via the signer link, opened in
    Legion PDF: both signatures render on their lines, dates burned as text
    (pdftotext confirms "8/22/2026" ×2 + certificate text), page count 3.
11. **Acrobat-compat export** — `buildFillableForm` produced real AcroForm
    text fields (verified by pdf-lib reload: 2 `PDFTextField`) + labeled
    "Sign here — <name>" guide boxes, rendered correctly by poppler (an
    independent viewer). In-app export button verified enabled/disabled
    states; native save dialog not automatable from the driver.

## Findings / notes

- **Driver `type` truncates some long strings** (a chat message cut off
  mid-word; signer emails never reached Centurion on the first ask —
  Centurion correctly refused to guess and asked). Workaround: set input
  values via `eval` + native setter. Driver-skill quirk, not a product bug.
- The first packaged/dev run stored E-Sign settings only after
  `LIBRARIUS_DEV=1` (WSL has no safeStorage keyring — expected dev-mode
  behavior; the error message reads correctly).
- Sent-request receipts don't survive an app relaunch (in-memory store,
  documented in TROUBLESHOOTING). The service status API remains the truth.
- ESIGN_API_KEY was rotated after the run (a fragment had appeared in a QA
  screenshot when a keystroke landed in the wrong input); current key lives
  in the Worker secret + the local creds file. Signing links for the test
  envelope are consumed (both signers signed; envelope complete).
